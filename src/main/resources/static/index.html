Timestamp Server – Admin interface

A simple interface for the /api/timestamp/* (RFC 3161 timestamp) and /api/ocsp/* (OCSP test responder) endpoints. Use the tabs to switch between the two services.

Warning: this server is intended for testing, and signing key replacement currently requires no authentication. Do not expose it publicly in a trusted environment.

Fixed timestamp time

When set, this time is used for every standard timestamp request (POST /api/timestamp). It may be in the past or future. Format: yyyy-MM-dd HH:mm:ssZ (24-hour), e.g. 2020-01-31 14:30:00+0200; UTC is used when no time zone is given. The time zone can be an offset (Z, +0200, +02:00), an abbreviation (UTC, CET, CEST, EET, EEST…) or a region (Europe/Budapest). A T can also separate the date and time. Saving an empty value restores the current time. This setting is kept in memory and cleared on server restart.

Timestamp with a custom time

Download a one-off RFC 3161 timestamp response (.tsr) for a file or hash, independently of the fixed time. The time may be in the past or future. Format: yyyy-MM-dd HH:mm:ssZ (24-hour), e.g. 2020-01-31 14:30:00+0200. UTC is used when no time zone is given; the time zone formats are described above. An empty time uses the current time.

Replace signing key

When enabled, only certificates with a critical timestamping EKU extension are accepted, as required by RFC 3161. When disabled, both critical and noncritical EKUs are accepted, but the EKU must still be exclusively for timestamping. A timestamp created with a noncritical EKU does not comply with RFC 3161 and may be rejected by strict validators; use this option only for testing.

OCSP test responder

Test only. Profiles and settings are lost on restart. The client must use ./api/ocsp/responder and validate at the simulated time. Never upload production keys.

The signing algorithm is selected automatically from the key (RSA, RSA-PSS, EC, DSA, EdDSA or ML-DSA).

Custom responder URL paths

Besides /api/ocsp/responder, the responder also answers (GET and POST) on these paths, to simulate the fixed OCSP URL of a certificate, e.g. /ca/ocsp.

Forward requests without issuer profile

When enabled, an OCSP request whose certificates match none of the issuer profiles is sent to this URL (HTTP POST) and its answer is returned unchanged, as if this server had answered. Off by default. A request that already came from a forwarding test server is not forwarded again.

Blacklist mode: every certificate of the selected issuer is GOOD unless listed here. Add REVOKED serials as exceptions; deleting a status restores the GOOD default. UNKNOWN answers the OCSP "unknown" status.
